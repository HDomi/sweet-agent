01 // 압축 비교

뭐가 사라지나

군더더기, 조사, 상투어, 완충 표현이 사라진다. 기술적 내용은 전부 그대로 남는다.

예시: React 리렌더 진단 긴 문단 → 한 줄
"React 컴포넌트가 리렌더링되는 이유는 렌더마다 새 객체 참조가 생성되고 있기 때문일 가능성이 높습니다. 생겨. 인라인 객체 prop = 새 참조 = 리렌더. 인라인 객체를 prop으로 전달하면 React의 얕은 비교가 매번 다른 객체로 인식하여 리렌더링이 발생합니다. useMemo를 사용해 객체를 메모이제이션하는 것을 권장합니다." useMemo로 감싸 오빠~
02 // 측정

아직 측정 안 했다

이 프로젝트는 영어 caveman 에서 갈라져 나왔다. 원본에는 "출력 토큰 65% 절감" 이라는 실측치가 있었지만, 그건 영어 압축 문체를 측정한 값이다. 한국어 반말은 압축되는 방식도, 토크나이저에서 문자당 토큰 수도 다르다. 근거 없는 숫자를 옮겨 적지 않기로 했으므로 지웠다.

직접 재려면 benchmarks/prompts.json 을 한국어로 채우고 benchmarks/run.py 를 돌리면 된다. 측정 전까지 /sweet-stats 는 실제 토큰 수만 보여주고 절감 추정은 생략한다 — 추측한 숫자를 내놓지 않는다.

줄어드는 건 출력 토큰뿐이다. 입력과 추론 토큰은 그대로고, 스킬 자체가 매 턴 입력 토큰을 추가한다. 이미 짧게 답하는 작업에서는 오히려 손해일 수 있다. 어느 쪽인지 판단하는 기준은 숫자에 대해 문서에 있다.

03 // 규칙

어떻게 동작하나

💀
상투어 제거
평범한 LLM 은 "네, 기꺼이 도와드리겠습니다", "~하시는 것을 고려해보시면 좋을 것 같습니다" 같은 말에 토큰을 쓴다. 스윗은 상투어, 완충 표현, 조사, 군더더기를 생성 단계에서 버린다.
✍️
코드 보존
코드 블록, 커밋 메시지, PR 설명은 압축을 거치지 않는다. 명령어, 파일 경로, 에러 문자열, API 이름은 영문 원문 그대로.
🧠
용어 정확성
기술 용어는 그대로 둔다. 새 약어를 만들지 않는다 — 설정→셋, 구현→임플 같은 축약은 토큰 절약이 0인데 해독 비용만 든다.
🛡️
자동 명확화
압축이 위험해지는 지점에서는 알아서 완전한 문장으로 돌아온다: 보안 경고, 되돌릴 수 없는 작업 확인(DROP TABLE, rm -rf, force push), 순서를 잘못 읽으면 안 되는 다단계 절차, 사용자가 못 알아들었을 때. 끝나면 다시 짧아진다.
